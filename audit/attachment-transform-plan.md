### PDF details

- Runtime is `pdfjs-dist` legacy build plus `sharp`. Lockfile resolves `pdfjs-dist` **5.7.284**, despite the manifest range beginning at 5.5.207.
- Metadata: source size/mtime, format, total page count, capped-page indication, title/author/subject/creator/producer/PDF version when present, and first-page dimensions in points and approximate millimetres.
- Text concatenates each PDF.js text item's `str`; `hasEOL` ends a line. An empty page receives an explicit no-text marker. A replacement engine may order text/ligatures differently, so equivalent text extraction needs paired fixtures rather than an assertion of byte-identical output.
- Preview resolves nested outline/bookmark destinations to one-based page numbers when possible, then emits **first-page text only**, no images, plus remaining-page count. Effective range is page 1.
- Full reads default to pages 1 through **min(total pages, 30)**. `start_page` is at least 1; `end_page` is at most that 30-page ceiling. This is a ceiling on absolute page index, not a sliding 30-page window. Requesting page 31 alone yields no page output in the pinned implementation; document any intentional correction rather than silently claiming exact equivalence.
- Each page checks `paintImageXObject` and repeated-image operations; duplicate object IDs are suppressed within that page. At most **10 images/page, 50/document**, each dimension at least **10 px**. Resolution is attempted from page objects, common objects, then a callback with a 3-second fallback timeout. Individual image failures are skipped.
- Decoded rasters are encoded as WebP quality **60**. Text and image parts are interleaved inside `<page>` / `<text-content>` / `<images>` markers. Preview does not include them. Encrypted, empty and malformed PDFs need explicit outcomes; the source supplies no password UI or OCR path here.
- Native bounds must precede decoded-pixel allocation. Metadata/outline nesting and aggregate text also need bounds: the source's constants do not cap every intermediate allocation. Do not preserve defects such as treating packed 1-bit image data as unpacked grayscale bytes.

### Archive details

- ZIP uses `yauzl` lazy entries; resolved lockfile is **3.3.0**. It reads names, trailing-slash directory status and uncompressed sizes, stopping at **2,000 entries**. ZIP64/name encoding details are delegated to that library.
- TAR manually reads 512-byte records, null-terminated 100-byte name plus USTAR prefix at bytes 345–499, octal size at 124–135 and type at 156. Regular files, directories and symlinks are listed. GNU long-name/PAX headers are skipped, not interpreted, while their body blocks are advanced over. Stop at the first zero block or entry limit. This is narrower than complete TAR support.
- `.tgz` and `.tar.gz` gunzip first. The upstream implementation accumulates all inflated chunks before its TAR listing cap; native streaming inflation must add a documented byte/work ceiling and early stop. `qUncompress()` is not a gzip decoder and is not an appropriate substitute.
- Implied parent directories are built from slash-separated paths. Metadata counts listed files/explicit directories and sums uncompressed sizes. No archive path ever becomes a filesystem destination.
- Preview renders depth 0; full default depth is 4. Shared `format-directory-tree.ts` sorts directories first, then names; per-depth visible-entry caps are **20, 10, 5** (last value repeats), plus **500 displayed entries** overall and truncation markers. Preserve these caps rather than merely taking the first 500 records.
- Test unsafe-looking member names as inert text, deep repeated components, malformed offsets/lengths, ZIP64, duplicate names, and gzip bombs. Do not execute archive helpers or create member paths.

### RAW and disk details

- RAW extension list in dispatch: NEF, CR2, CR3, ARW, DNG, ORF, RW2, RAF, PEF, SRW, ERF, 3FR, RWL, MRW, NRW, RAW.
- Source asks `sharp().metadata()` for TIFF/container properties first. EXIF parsing follows little/big-endian IFD entries and EXIF/GPS pointer tags; selected fields are make, model, orientation, date/time, exposure, aperture, ISO, focal length, 35 mm equivalent and lens model. Its recursive IFD traversal has no visited-offset/depth guard. A native port should use checked arithmetic, bounded tag counts/strings, a visited set and a recursion cap.
- Source JPEG scan pairs each SOI with the next EOI, moves past it, and chooses the largest candidate of at least **10,000 bytes**. Decoding failure produces text fallback. Success adds preview dimensions and WebP quality **70**. This heuristic does not promise every RAW container or embedded thumbnail is decoded. Qt JPEG/WebP plus a bounded TIFF/EXIF reader can cover this actual behavior without adding LibRaw.
- ISO requires a type-1 `CD001` PVD exactly at sector **16**, sector size **2,048**, volume label at PVD bytes 40–71 and root directory record at 156. Directory records use little-endian LBA/size fields, flag bit 0x02, identifiers at byte 33; `.`/`..` are skipped, `;version` and trailing dots stripped. Padding skips to the next sector. Recursion is capped by default depth + 1 and **500 total entries**. Render uses the same tree policy as archives.
- There is no Joliet, Rock Ridge, UDF, partition-table, FAT/NTFS, VHD/VHDX or writable/mounted-disk inspection promise. IMG that is not ISO9660 falls back. Native ISO parsing can port these small semantics with bounded extents and cycle detection, without mounting anything.

### Source, Markdown and SVG details

- Language grammar families: TypeScript, TSX, JavaScript (JS/JSX/MJS/CJS), Python, Go, Rust, Java, CSS, Bash (SH/BASH/ZSH), Ruby, PHP, C#, C++ (also C/H/HPP). HTML/XML/JSON/YAML/TOML/SQL/Kotlin/Scala/Swift/Vue/Svelte and SCSS/LESS have no grammar in the pinned map and fall back to text. Markdown/SVG have dedicated text transforms.
- Lockfile resolves `web-tree-sitter` **0.26.8** and `@vscode/tree-sitter-wasm` **0.3.1**. Native equivalents should use the C runtime and generated grammar C/scanner sources, not execute WASM through Node. Grammar ABI compatibility and semantic output require tests for every family.
- `symbol-extractor.ts` has language-specific traversal, exported flags and nested members. TSX/JSX additionally inspect function bodies. It is not enough to use a generic function-name query. Signatures stop at the declaration body or first source line, collapse newlines, strip the Python colon, and cap at **120 characters**. Preserve UTF-8 byte offsets versus QString/UTF-16 indexes correctly.
- Outline rendering starts with the complete symbol tree, prunes deepest levels to retain breadth, then drops excess top-level symbols. Output includes one-based line numbers and explicit pruning notices. Parser failure or no symbols returns ordinary first-N-lines preview. Full text and line ranges bypass AST parsing.
- The currently published Microsoft's 0.3.1 build source names C# output `tree-sitter-c_sharp.wasm`, while Stagewise's map asks for `tree-sitter-c-sharp.wasm`. This is a source discrepancy to verify against the exact package payload/reference runtime before calling it a reproduced defect. Do not infer all C# preview tests should silently pass from the advertised map.
- Markdown preview uses ATX `#` headings (1–6), each range ending before the next equal/higher-level heading or EOF, plus the first **15 numbered lines**. Setext headings are not recognized; the regex does not skip fenced-code headings. These source quirks need explicit fixtures. Full/range output is ordinary bounded text. SVG markup remains text with normal preview/range handling.

## Native dependency path

No dependency was vendored or compiled during this audit. Proposed version pins must be resolved and recorded with source archive hashes before implementation; moving `main`/`master` URLs below are evidence for API/build options, not reproducible build inputs.

1. **Trees/text/ISO/RAW first:** QtCore plus current Qt image plugins suffice for Markdown/SVG/tree rendering, bounded ISO parsing and RAW JPEG preview. Keep direct ports under the upstream attribution. Do not add LibreOffice/COM, LibRaw, disk mounting or Node to cover behaviors the reference does not perform.
2. **Archives:** prefer a small static libarchive build restricted at runtime to ZIP/TAR plus gzip, with header iteration only and no disk writer/external-program filters. Official [libarchive](https://libarchive.org/) lists MinGW support and a New BSD license. Preserve root `COPYING` and all included source notices under proposed `third_party/libarchive`; its own `COPYING` says per-file notices control. [CMakeLists.txt](https://github.com/libarchive/libarchive/blob/master/CMakeLists.txt) exposes shared-library, CLI, compression, crypto and XML feature toggles. Disable unused tools/crypto/XML/compressors explicitly and link one audited zlib, not ambient DLLs. More capable TAR/ZIP decoding must be distinguished from exact source quirks. Alternative for strict smallest scope: bounded ZIP central-directory/ZIP64 + TAR parser with streaming zlib; this reduces dependencies but enlarges the project's parser audit burden.
3. **AST:** vendor Tree-sitter C runtime (`lib/src/lib.c`, `lib/src`, `lib/include`) plus pinned generated `src/parser.c` and any scanner sources/headers for all 13 grammar families, preserving each grammar's own LICENSE and provenance under `third_party/tree-sitter*`. The [official integration guide](https://tree-sitter.github.io/tree-sitter/using-parsers/1-getting-started.html) documents embedding `lib.c` and compiling generated parsers directly; no generation CLI is needed at runtime. Core [LICENSE](https://github.com/tree-sitter/tree-sitter/blob/master/LICENSE) is MIT. Do not assume the umbrella WASM package's MIT label substitutes for all grammar notices. Microsoft's [build source](https://github.com/microsoft/vscode-tree-sitter-wasm/blob/main/build/main.ts) and package lock identify source packages/commits; use exact 0.3.1 payload/provenance to pin before vendoring. Current build source pins C# `485f0bae0274ac9114797fc10db6f7034e4086e3`, C++ `12bd6f7e96080d2e70ec51d4068f2f66120dde35`, Rust `261b20226c04ef601adbdf185a800512a5f66291`; other families are package versions. These observations need release-payload verification before they become build inputs.
4. **PDF:** strongest functional candidate is the MuPDF C API, using structured text with image preservation and document outline/metadata. The [structured-text options](https://mupdf.readthedocs.io/en/latest/reference/common/stext-options.html) expose preserved images; this is closer to the reference than rasterizing whole pages. MuPDF is [AGPL or commercially licensed](https://mupdf.readthedocs.io/en/latest/license.html); this repo already contains AGPLv3, but bundled third-party notices and actual distribution obligations still need inclusion, not an unsupported legal-compatibility guarantee. Preserve `COPYING`, pinned source, build recipe and each included `thirdparty/*` notice under proposed `third_party/mupdf`. Its [dependency inventory](https://mupdf.readthedocs.io/en/latest/other/third-party.html) includes patched font/image/color/deflate libraries; do not swap in Qt internals as ABI-compatible without proof. Disable document JavaScript execution, networking, viewers and unrelated conversion/OCR features in our integration. **MinGW-static feasibility remains unproven**: official [Windows build instructions](https://mupdf.readthedocs.io/en/latest/guide/install.html) use Visual Studio, not our toolchain. First action after release is an isolated static link/read fixture spike, not root CMake changes. If that fails, evaluate pinned PDFium C API or Poppler with explicit licensing/toolchain evidence. QtPdf's public API exposes text and page rendering, but not a direct embedded-image extraction contract, and it is not installed; rebuilding QtPdf alone cannot be claimed to match all PDF behavior.

## Required pipeline seams, beyond individual transformers

The current 16-pass attachment fixture suite covers the first text/image/persistence slice only. Full transformation parity needs a reusable service consumed by both user attachments and explicit model file reads; adding file extensions only in the composer will leave the tool path incomplete.

- Add a value `FileReadParams` with optional inclusive one-based line/page ranges, optional depth and preview flag. Add `FileTransformResult` with text/image parts, metadata, actual delivered read parameters and an explicit truncation/error indication. Use the existing canonical multipart representation consumed by all four provider serializers.
- Keep `AttachmentPipeline::capture` and immutable message `metadata.attachments` / `metadata.pathReferences`. Read source bytes from existing same-handle workspace/store guards or historical snapshots; no transformer receives filesystem authority or network credentials. Original extension uses `originalFileName` for randomized `att/` blobs.
- Request preparation uses workspace preview, uploaded full content, and explicit `read` parameters as the source does. Extend the current native `read` schema and keep `ls` separate; do not register the stale `readFile` tool alias. Raw binary `fs.readFile` is a distinct broker contract and must not receive formatted text by accident.
- Record explicit read results in history and preserve tool call/result pairing. Media generated by transforms uses the same synthetic user-message placement after contiguous tool results. Provider capability adaptation reruns on each model fallback. Never mutate provider-owned signed assistant blocks or embed local-only metadata on the wire.
- Cache transformed results by agent + captured content hash + extension + parameters + transformer version. Cache processed images separately by original content hash + actual model constraints/encoding policy. Bound entries, bytes and intermediates, preserve clone/archive/delete behavior, and try historical cached data before a changed/deleted workspace file. Existing snapshots preserve originals; transformed/encoded-result caches are still additional work.
- Deduplicate repeated mention/upload `(path,hash)` pairs within one prepared history, while explicit model `read` calls always return their requested representation. Coverage/truncation must reflect what was delivered, not infer that a 30-page preview read the entire PDF. Cancel expensive transforms and ignore late results using host generation IDs; existing synchronous preparation will need an async seam or isolated native worker for bounded long-running decoders.
- File contents, names, headings and metadata remain untrusted context. Escape wrapper attributes/delimiters appropriately; do not treat content as new tool authorization or execute document scripts/macros/links. No automatic remote fetching or plugin credential forwarding is needed by these transforms.
