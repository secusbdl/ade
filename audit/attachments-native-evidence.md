# Native attachment persistence and model-input slice

The implemented slice is `src/attachments`, with compatible seams in AgentEngine, ProviderProtocol and utility serialization. It covers uploaded/pasted bytes, workspace file references, UTF-8 text, raster images, binary persistence, tool-created media references, and image request serialization for the four native provider protocols. It performs no live uploads during verification.

## Native contracts

`AttachmentStore` persists originals in `dataDir/attachments/<agentId>` and snapshots in `dataDir/attachment-snapshots/<agentId>`. `importFile` keeps in-workspace references and copies outside selections using temporary-file/flush/no-replace installation; `write` stores pasted/generated bytes. `existingBlob` adopts a validated worker-generated filename in the same per-agent storage. Original filenames remain display metadata, not filesystem destinations.

Windows reads open one handle, resolve and check that handle's final path, then read from that same handle; no delete-sharing is granted during the read. Workspace/attachment traversal and NTFS junction escape are rejected. Clone reads use the same validation. Cleanup is limited to prevalidated flat per-agent files; unexpected subdirectories/links stop deletion. Fork copies both originals and snapshots. Archive requires no deletion.

`AttachmentPipeline::capture` returns `{attachments,pathReferences}` for persistent message metadata. Its `prepare` method returns a separate request-only message array; stored user/tool text and provider-owned signed blocks remain unchanged. Snapshots bind agent, path and hash, are hash-verified on reuse, survive restart/source changes/deletion, and cannot be fetched through an uncaptured path or another agent. The persistent cache is bounded to 500 entries and 512 MiB per agent with access-time LRU; a 128 MiB memory cache reduces repeated reads. Cache eviction can make old changed/deleted workspace content unavailable; the model receives an explicit fallback instead of current unrelated bytes.

The image pass uses Qt decoders/encoders, auto-orientation, dimension/pixel downscaling and quality steps 80/65/50. It serializes supported images as OpenAI chat `image_url`, Responses `input_image`, Anthropic base64 image source, or Google `inlineData`. Local metadata is removed from wire messages. Text-only models receive an explicit image-unavailable marker. Fallback requests rerun preparation against the actual next model's capabilities.

AgentEngine additions preserve existing callers: `submitWithAttachments(text,refs,pathReferences)`, `setMessagePreparer(callback)`, and `completeExternalToolWithAttachments(id,output,error,refs,pathReferences)`. History stores `metadata.attachments` and `metadata.pathReferences`; inline image bytes appear only in transient provider requests. Utility title/compression prompts include attachment paths/names, not binary data.

## Verification

Independent static MinGW/Qt 6.11.2 build in `private/attachments-probe-build`:

- `test-results/attachments-tests.txt`: **16 passed, 0 failed, 0 skipped**, including actual AgentEngine loopback HTTP requests for all four provider protocols, model fallback from image-capable to text-only, cancellation/preparation failure, original-history preservation, metadata-free wire payloads, signed assistant block preservation, and correct tool-call/result ordering.
- Persistence fixtures cover binary exact-byte preservation, workspace versus uploaded references, restart/fork/delete, real NTFS junction rejection, snapshots after source deletion/change, empty-file snapshots, corruption refusal, agent/path isolation, UTF-8 trailing-sequence fallback, image scaling/byte budgets, and the pinned model table.
- `test-results/core-tests.txt`: **36 passed, 0 failed, 0 skipped** after the engine/protocol seams.

All file content was generated by the tests and all network requests used local fixture providers. No real user file was uploaded and no provider key was used.

## Explicit remaining scope

- Upstream PDF text/embedded-image extraction, archive trees, RAW-camera previews, disk-image inspection, AST source previews and richer Markdown transformations are not implemented in this slice. Recognized advanced binary formats are preserved with an explicit unavailable-transform message. QtPdf is not installed in this static toolchain. AVIF decoding depends on an unavailable codec; no AVIF parity is claimed.
- Audio/video and Office binaries are not sent as fabricated text or unsupported image parts. Native file/audio/video wire adapters remain separate work.
- Native local import is capped at 100 MiB, transformer reads/snapshots at 64 MiB, decoded image dimensions at 64 megapixels, and per-request inline image data at 20 MiB. The pinned Google table permits larger inputs; the native ceiling is an explicit current limit.
- The cache stores original captured bytes rather than upstream's SQL transformed-result cache, preserving data semantics while using a different native implementation. A model's allowed format/size may still reject a request outside the tested fixtures; no live multimodal entitlement was tested.
- `att/` access from the sandbox file broker, attachment viewer/editor UX, and session draft/fork/delete wiring belong to host/UI integration and need their own integrated evidence. This module does not claim every upstream file transformer or full attachment UX parity.
